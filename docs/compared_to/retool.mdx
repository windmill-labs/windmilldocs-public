# Open source Retool alternative for internal tools

<a href="https://retool.com/" rel="nofollow">Retool</a> is a proprietary platform for building internal apps, workflows and agents on a visual canvas, wired to databases and APIs with JavaScript, SQL and, in workflows, Python.
Windmill covers the same ground as an open-source, self-hostable platform: apps, flows and scripts run on one runtime, and every piece of logic is a script you can also run on its own, on a schedule or behind a webhook.

This page compares Windmill and Retool section by section, with the plan each feature needs on either side.
For a visual side-by-side of both products, see the [Windmill vs Retool comparison page](/compare/retool).

## Windmill vs Retool at a glance

Both platforms build internal apps.
The difference is what else runs on the same runtime.

| What you can build | Windmill | Retool |
| --- | --- | --- |
| Low-code internal apps: drag-and-drop dashboards and admin tools with a built-in component library | Yes | Yes |
| Full-code internal apps: custom dashboards and admin tools built in React or Svelte | Yes | Partial |
| Workflows: chain steps into flows with branching, retries and approval steps | Yes | Yes |
| Scripts: standalone functions exposed as APIs, webhooks or cron jobs with their own UI | Yes | No |
| Data pipelines: ETL, syncs and scheduled data jobs with parallel branches | Yes | Partial |
| AI agents with tool calling | Yes | Yes |
| AI sandboxes and volumes: isolated environments with persistent volumes for running agents | Yes | No |
| Scheduled tasks: cron jobs with retries, error handling and alerting | Yes | Yes |

Windmill centralizes scripts, workflows, data pipelines, full-code apps, AI agents and operator UIs on a single runtime, with shared resources, auth and observability.
Retool is app-builder first, with Workflows and Agents layered on the same visual canvas.

## Who each platform is built for

Windmill is built for developer-led teams where engineers own the platform end to end: code, Git, local development, workspace forks, code review, CI/CD, AI coding tools and infrastructure as code.
Non-developers use what engineers build through auto-generated UIs, custom apps and run-only workspace roles.
They can build simple apps with AI assistance, but authoring scripts and flows still involves writing code.

Retool is built for developers and low-code engineers building internal tools.
The canvas-first editor suits people who think visually and write short JavaScript or SQL for glue logic.
Its drag-and-drop app canvas is approachable for non-developers who can read a bit of JavaScript, while Workflows still require real code.

## Open source and self-hosting

Windmill's Community Edition is open source under AGPLv3 and can be self-hosted for free with Docker Compose or Kubernetes.
The [Windmill Hub](https://hub.windmill.dev/) is a public library of scripts, flows and apps that anyone can contribute to.

Retool is closed source and has no open-source edition.
On its <a href="https://retool.com/pricing" rel="nofollow">pricing page</a>, deploying Retool self-hosted or air-gapped is part of the Enterprise plan; Free, Team and Business run on Retool Cloud.

## Languages and logic

Retool apps use JavaScript for transformers and event handlers and SQL for queries.
Retool Workflows add <a href="https://docs.retool.com/workflows/guides/blocks/code" rel="nofollow">code blocks in JavaScript and Python</a>.

In Windmill, logic is a script in [TypeScript](../getting_started/0_scripts_quickstart/1_typescript_quickstart/index.mdx), [Python](../getting_started/0_scripts_quickstart/2_python_quickstart/index.mdx), [Go](../getting_started/0_scripts_quickstart/3_go_quickstart/index.mdx), [Bash](../getting_started/0_scripts_quickstart/4_bash_quickstart/index.mdx), [SQL](../getting_started/0_scripts_quickstart/5_sql_quickstart/index.mdx), [PHP](../getting_started/0_scripts_quickstart/8_php_quickstart/index.mdx), [Rust](../getting_started/0_scripts_quickstart/9_rust_quickstart/index.mdx), [C#](../getting_started/0_scripts_quickstart/11_csharp_quickstart/index.mdx), [Java](../getting_started/0_scripts_quickstart/13_java_quickstart/index.mdx), [Ansible](../getting_started/0_scripts_quickstart/10_ansible_quickstart/index.mdx) and [more](../getting_started/0_scripts_quickstart/index.mdx), or a [Docker container](../getting_started/0_scripts_quickstart/7_docker_quickstart/index.mdx).
Dependencies are [resolved from the imports](../advanced/6_imports/index.mdx) and pinned per script, with no package.json or requirements.txt to maintain.
Each script is also a standalone endpoint with an [auto-generated UI](../core_concepts/6_auto_generated_uis/index.mdx), a [webhook](../core_concepts/4_webhooks/index.mdx) and [schedules](../core_concepts/1_scheduling/index.mdx), so the same code serves an app, a flow and an API.

## Workflows

Retool Workflows run on a separate canvas with blocks for code, resource queries, loops and branches.
They start from <a href="https://docs.retool.com/workflows/concepts/triggers" rel="nofollow">schedules, webhooks and query triggers</a> (in beta).
Workflow runs are metered: the pricing page lists 500 runs a month on Free and 5,000 on Team, with additional runs at $75 per 5,000.

Windmill [flows](../flows/1_flow_editor.mdx) chain scripts in any of the languages above, with [approval steps](../flows/11_flow_approval.mdx), [sleep](../flows/15_sleep.md), [early stop](../flows/2_early_stop.md), [while loops](../flows/22_while_loops.mdx), retries and error handlers.
They start from schedules, webhooks, HTTP routes, or event triggers for [Kafka](../triggers/5_kafka_triggers/index.mdx), NATS, SQS, MQTT, Postgres, WebSocket and email.
[Kafka](../triggers/5_kafka_triggers/index.mdx), [NATS](../triggers/6_nats_triggers/index.mdx) and [SQS](../triggers/7_sqs_triggers/index.mdx) triggers are self-hosted Enterprise features, and [Postgres](../triggers/4_postgres_triggers/index.mdx) and [MQTT](../triggers/8_mqtt_triggers/index.mdx) triggers are not available on Windmill Cloud.
Self-hosted Windmill, on Community and Enterprise Edition, has no execution limit: you size the workers that run the flows. On Windmill Cloud, the free plan includes 1,000 executions a month and the Team plan 10k per user.

## Apps

Both products have a drag-and-drop app builder connected to queries and backend code.
Windmill also lets you build [full-code apps](../full_code_apps/index.mdx) in React or Svelte, backed by the same scripts and flows.

## Developer experience and Git

Windmill can be used entirely from your own tools: the [CLI](../advanced/3_cli/index.mdx), [local development](../advanced/4_local_development/index.mdx) in VS Code or with Claude Code, and [Git sync](../advanced/11_git_sync/index.mdx), which writes every script, flow, app and trigger to a repository as files.
Git sync is free on self-hosted Community Edition for up to 2 users.

[Full-code apps](../full_code_apps/index.mdx) are React or Svelte source trees in your repository: edit them in VS Code, preview with a local dev server, and deploy with the CLI or Git sync.
The scripts and flows behind an app are edited and tested locally the same way, so AI coding tools such as Claude Code and Codex work against real source files.

Retool apps are edited in Retool's web editor.
<a href="https://docs.retool.com/source-control" rel="nofollow">Source Control</a> syncs apps and workflows to GitHub, GitLab, Bitbucket, AWS CodeCommit or Azure Repos through pull requests, and the pricing page lists it on the Enterprise plan.
Lower tiers rely on app release versions inside Retool.

## Data, resources and secrets

Windmill has [data tables](../core_concepts/11_persistent_storage/data_tables.mdx) with SQL queries and a browse and edit UI, kept separate from apps, plus [workspace object storage](../core_concepts/38_object_storage_in_windmill/index.mdx) on S3 for large payloads and files shared across scripts, flows and apps (capped at 10 GiB per workspace on Community Edition, unlimited on Enterprise).
[Resources](../core_concepts/3_resources_and_types/index.mdx) (typed JSON for credentials and connection settings) and [variables and secrets](../core_concepts/2_variables_and_secrets/index.mdx) are reusable across scripts, flows and apps, encrypted at rest, scoped by folders and groups, and versioned in Git.
External secret backends such as Vault and AWS Secrets Manager are an [Enterprise](/pricing) feature.

<a href="https://retool.com/database" rel="nofollow">Retool Database</a> is a hosted Postgres for app data with a browse and edit UI, with unlimited rows up to 5 GB of storage on every cloud plan.
External databases connect as resources, and files go through the File component and the AWS S3 resource.
Resources and environment variables are configured at the organization level and encrypted at rest; external secret managers are on Enterprise.

## Integrations

Retool ships a catalog of pre-built <a href="https://retool.com/integrations" rel="nofollow">integrations</a> for databases, SaaS and AI providers, and falls back to a generic REST or GraphQL resource or a JavaScript code block for anything else.
Retool supports <a href="https://docs.retool.com/apps/guides/custom" rel="nofollow">custom components</a>, and custom auth or connectors often go through a generic REST resource with JavaScript transformers.

In Windmill, any npm, PyPI, Go or Maven package is an integration, since scripts import it directly and call the vendor's own SDK, with dependencies resolved and pinned per script.
[Resource types](../integrations/0_integrations_on_windmill.mdx) describe connections to databases, SaaS and infrastructure, and anyone can add one.
A new integration is a script with a new import, with no plugin release to wait for.
The [Hub](https://hub.windmill.dev/) has reusable scripts and flows for common tasks.

To receive events, every Windmill script and flow has an HTTP endpoint and a [webhook](../core_concepts/4_webhooks/index.mdx), and [triggers](../triggers/index.mdx) consume Kafka, NATS, SQS, MQTT, Postgres changes, WebSocket and email directly.
[Kafka](../triggers/5_kafka_triggers/index.mdx), [NATS](../triggers/6_nats_triggers/index.mdx) and [SQS](../triggers/7_sqs_triggers/index.mdx) triggers are self-hosted Enterprise features, and [Postgres](../triggers/4_postgres_triggers/index.mdx) and [MQTT](../triggers/8_mqtt_triggers/index.mdx) triggers are not available on Windmill Cloud.
Retool Workflows start from schedules, webhooks and query triggers; event sources such as Kafka consumers or database change streams need polling or an external bridge.

## Migration and lock-in

Getting into Windmill: paste a function body into the script editor, and Windmill infers the arguments, generates a UI and resolves dependencies.
Apps, triggers, schedules and variables move over one by one.
Getting into Retool is fast if you already think in drag-and-drop apps wired to queries, and Retool can also create apps <a href="https://docs.retool.com" rel="nofollow">from imported React code</a>.

Getting out of Windmill: step logic is standard TypeScript, Python, Go, Bash or SQL that runs anywhere, and the [CLI](../advanced/3_cli/index.mdx) exports the workspace as plain files.
What you lose when leaving Windmill is the runtime, not the code.
Retool apps are stored in Retool's own canvas format.
With Source Control (Enterprise), apps and workflows sync to Git as Retool-specific files that do not port to another platform without a rewrite.
JavaScript and SQL inside queries are portable; the layout and component bindings are not.

## Where Retool is ahead

Retool has a large library of <a href="https://retool.com/templates/" rel="nofollow">templates</a> and a broad <a href="https://docs.retool.com/classic-apps/reference/components/" rel="nofollow">component library</a>, and its canvas is approachable for people who write a little JavaScript.
If your team builds CRUD screens over a database and does not need other languages, self-hosting or Git outside Enterprise, Retool is a reasonable choice.

Windmill fits better when internal tools are one part of a wider estate of scripts, workflows, data pipelines and AI agents that you want to run on your own infrastructure, review in Git and pay for by compute rather than by run.

## FAQ

### Is Windmill a drop-in replacement for Retool?

For internal apps, yes, with caveats.
Windmill has a visual app builder with a component library similar to Retool's, plus full-code apps in React or Svelte that live as source trees in your repository.
Porting means rebuilding apps component by component, since Retool's canvas definition is not directly importable.
Teams that rely on Retool's wider widget catalog (mobile-specific components, some specialty inputs) should check component parity before committing to a migration.

### Can I migrate Retool apps to Windmill automatically?

No.
Migrations are manual rebuilds: each query becomes a Windmill script and each component maps to the closest Windmill equivalent.
Because Windmill scripts have their own API endpoints, many of the rebuilt queries can then be reused outside the app as webhooks, scheduled jobs or flow steps.

### Is Retool open source?

No.
Retool is proprietary and closed source, and self-hosting is on the Enterprise plan.
Windmill's core is open source under AGPLv3 and free to self-host, with Enterprise features in a separate proprietary codebase.

### Does Windmill support JavaScript and SQL queries the way Retool does?

Yes.
Windmill scripts can be written in TypeScript, JavaScript, Python, Go, Bash, SQL, PHP, Rust, C# and more, or run a Docker container.
For SQL, both platforms run raw queries against connected databases.

### Is Retool better for non-technical users who want to build apps?

On the app-building side, Retool is more polished for that audience: a deeper component library, more mature drag-and-drop interactions, and an editor that assumes no CLI or Git.
Windmill has a visual app builder too, but authoring queries involves writing code.
If your main users are analysts assembling CRUD screens over a single database, Retool is often faster to stand up; if the team is developer-led or ships code-driven automations next to its apps, Windmill fits better.
