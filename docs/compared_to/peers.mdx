# Windmill alternatives: when to pick something else

The closest alternatives to Windmill are n8n and Zapier for app automations, Kestra, Airflow, Prefect and Dagster for data and infrastructure pipelines, Temporal and Hatchet for durable execution in application code, Retool, Appsmith and ToolJet for internal UIs, and Rundeck for operations runbooks.
Each of them is the better choice for some teams.
This page says, for each one, when we would point you to it instead of Windmill, and when Windmill fits better.

Windmill writes this page, so read it with that bias in mind.
Facts about other tools are quoted from their own sites and repositories, checked on November 11, 2026.
For a detailed side-by-side with one tool, see the [comparison pages](/compare).
If something here is wrong or out of date, write to [contact@windmill.dev](mailto:contact@windmill.dev).

## What Windmill is, in one paragraph

Windmill runs scripts in more than 20 languages (TypeScript, Python, Go, Bash, SQL, PowerShell, Rust, C# and others) as jobs on workers you host or on Windmill Cloud.
The same scripts are chained into [flows](../flows/1_flow_editor.mdx), started by [schedules](../core_concepts/1_scheduling/index.mdx), [webhooks](../core_concepts/4_webhooks/index.mdx) and [other triggers](../triggers/index.mdx), paused on [approval steps](../flows/11_flow_approval.mdx), and given a UI through [auto-generated forms](../core_concepts/6_auto_generated_uis/index.mdx) and [apps](../full_code_apps/index.mdx).
The core is open source under AGPLv3, with some features reserved to the [Enterprise Edition](/pricing) (see [what the Community Edition does not include](#what-the-community-edition-does-not-include)).
Each script resolves its own dependencies from its imports and pins them in a lockfile when it is saved.
Workflow state is persisted in PostgreSQL, and Windmill is an at-least-once engine: after an infrastructure crash it recovers automatically, so steps where duplicates matter should be idempotent.
If your problem is only one of those pieces, a tool built for that piece may suit you better.

## Workflow automation with pre-built integrations

### n8n

n8n is a "fair-code platform to build and deploy AI agents and workflows" ([README](https://github.com/n8n-io/n8n)), built on a visual canvas with JavaScript and Python code nodes.
Its homepage lists "500+ native integrations" ([n8n.io](https://n8n.io/)).
It is source-available under the [Sustainable Use License](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), and self-hosted Community Edition is free.

Pick n8n when most of each workflow is pre-built nodes for SaaS apps, the people building them prefer a canvas to code, and an n8n node already exists for the services you use.

Windmill fits better when most steps are your own code: each step is a standalone script with its own dependencies, installed from its imports, that you can also run on its own, schedule, or expose as a form.
On n8n Cloud, the Code node cannot import external npm modules or Python libraries; on a self-hosted n8n, Python modules must be in the `n8nio/runners` image and allowlisted ([n8n docs](https://docs.n8n.io/build/code-in-n8n/using-the-code-node)).
See [Windmill vs n8n](/compare/n8n).

### Zapier and Make

Zapier "connects to 9,000+ apps" ([zapier.com/pricing](https://zapier.com/pricing)) and Make lists "3,500+ pre-built apps" ([make.com/llms.txt](https://www.make.com/llms.txt)).
Both are hosted services aimed at people who do not write code, with code steps available ([Code by Zapier](https://zapier.com/apps/code/integrations), the [Make Code app](https://help.make.com/the-make-code-app-is-available.md) on paid plans).
We found no self-hosted plan for either.

Pick Zapier or Make when non-developers own the automations, the work is moving data between SaaS apps, and a hosted service is acceptable.

Windmill fits better when developers own the automations, the logic is code you want in Git, or the workflows must run inside your network.
See [Windmill vs Zapier](/compare/zapier) and [Windmill vs Make](/compare/make).

### Pipedream

Pipedream Workflows [shuts down on March 31, 2027](https://pipedream.com/docs/workflows); Pipedream Connect continues.
Workday [signed a definitive agreement to acquire Pipedream](https://newsroom.workday.com/2025-11-19-Workday-Signs-Definitive-Agreement-to-Acquire-Pipedream) in November 2025.
Pipedream's [component registry](https://github.com/PipedreamHQ/pipedream) is public under the Pipedream Source Available License, which excludes "any commercial use of the software".
If you are leaving Pipedream Workflows, see [Pipedream alternatives after the Workflows shutdown](./pipedream_alternatives.mdx) for the options, including tools other than Windmill.

## Data and infrastructure orchestration

### Kestra

Kestra is an "open-source orchestration platform for data, AI, and infrastructure workflows" ([README](https://github.com/kestra-io/kestra)), with flows declared in YAML and a no-code editor and AI Copilot that "all edit the same flow".
It lists "2,600+ plugins" ([kestra.io](https://kestra.io/)) and is Apache 2.0.

Pick Kestra when you want pipelines declared in YAML, an Apache 2.0 license, and a plugin already exists for most of the systems you orchestrate.

Windmill fits better when the steps are code you write: in Windmill the Python or TypeScript file is the unit you run, test and reuse, and the flow only wires them together.
Kestra's form UIs ([Apps](https://kestra.io/docs/enterprise/scalability/apps)) are Enterprise only; Windmill's auto-generated forms and apps are in the Community Edition.
Kestra's open-source [Pause task](https://kestra.io/docs/how-to-guides/pause-resume) waits for someone to click Resume, and the pricing page lists Human-in-the-Loop Approvals with custom inputs as Enterprise ([kestra.io/pricing](https://kestra.io/pricing)).
Windmill approval steps are in the Community Edition, with forms and approver permissions on a Cloud plan or Enterprise.
In our [benchmarks](../misc/3_benchmarks/competitors/kestra/index.mdx), Kestra sat in the mid-tier: decent on long-running tasks, slower orchestration on short task loads.
See [Windmill vs Kestra](./kestra.mdx).

### Apache Airflow

Airflow is "a platform created by the community to programmatically author, schedule and monitor workflows", with pipelines "defined in Python" ([airflow.apache.org](https://airflow.apache.org/)).
It has "more than 80 providers" ([providers docs](https://airflow.apache.org/docs/apache-airflow-providers/)), is Apache 2.0, and is offered as a managed service by third parties, including Astro, Google Cloud Composer and Amazon MWAA ([ecosystem](https://airflow.apache.org/ecosystem/)).

Pick Airflow when your team already runs it, your pipelines are Python DAGs, and you want the largest pool of engineers and managed providers who know it.

Windmill fits better when the work is not only Python data pipelines, when you want to test each step on its own from a form before deploying, or when short tasks make scheduling overhead matter: see the [benchmarks](../misc/3_benchmarks/competitors/index.mdx).
See [Windmill vs Airflow](/compare/airflow).

### Prefect and Dagster

Prefect is "a workflow orchestration framework for building data pipelines in Python" that uses `flow` and `task` decorators ([README](https://github.com/PrefectHQ/prefect)).
Dagster is "a cloud-native data pipeline orchestrator" in which you declare the data assets you want to build as Python functions ([README](https://github.com/dagster-io/dagster)).
Both are Apache 2.0, and Prefect Cloud has a free Hobby tier ([prefect.io/pricing](https://www.prefect.io/pricing)).

Prefect [announced its acquisition of Dagster Labs](https://www.prefect.io/prefect-acquires-dagster) on July 13, 2026.
Dagster's own [announcement](https://dagster.io/blog/prefect-is-acquiring-dagster) says "Dagster continues under the Dagster brand" and that the open-source project "will be actively developed, not just maintained".
Dagster's [page for customers](https://dagster.io/prefect) says deployments, contracts, pricing and support remain unchanged.

Pick Prefect when your team writes Python and wants to orchestrate existing Python functions with decorators.
Pick Dagster when you think in data assets (tables, models, reports) and want lineage between them.

Windmill fits better when the pipeline mixes languages, includes SQL, Bash or TypeScript steps, or needs UIs and approvals around it.
Windmill also has [workflows as code](../core_concepts/31_workflows_as_code/index.mdx) for teams that prefer Prefect's style, and an [asset](../core_concepts/52_assets/index.mdx) graph.
See [Windmill vs Prefect](./prefect.mdx) and [Windmill vs Dagster](/compare/dagster).

### dbt

dbt is not an orchestrator.
It compiles SQL models into a DAG and runs them against your warehouse; something else schedules that run and puts the rest of the pipeline around it.

Windmill runs dbt rather than replacing it: a dbt project is [a script language of its own](../getting_started/0_scripts_quickstart/16_dbt_quickstart/index.mdx), unmodified, and its models land on the same asset graph as the Python and DuckDB scripts around them.
So the comparison is not with dbt Core but with dbt Cloud, or with orchestrating dbt from Airflow.
Keep dbt Cloud if its IDE and hosted scheduling are what you need.
See [Windmill vs dbt](/compare/dbt).

## Durable execution in application code

### Temporal

Temporal is "a durable execution platform that enables developers to build scalable applications without sacrificing productivity or reliability" ([README](https://github.com/temporalio/temporal)).
You write workflows with its SDKs, which officially support Go, Java, Python, TypeScript, .NET, Ruby, PHP and Rust ([SDK docs](https://docs.temporal.io/encyclopedia/architecture/temporal-sdks)), and its docs state: "A Temporal Application can run for seconds or years in the presence of arbitrary load and failures."
The server is MIT licensed; Temporal Cloud starts with $150 of free credits ([temporal.io/pricing](https://temporal.io/pricing)).

Pick Temporal when durable workflows are part of your product's own code, written by software engineers who want fine control over execution, and you run them inside your services.
In our [benchmarks](../misc/3_benchmarks/competitors/index.mdx), Temporal had the top throughput in Go multi-worker scenarios.

Windmill fits better when the workflows are internal automation rather than product code: each step is a plain script with a `main` function, and you get the editor, the run history, the forms and the schedules without building workers around an SDK.
See [Windmill vs Temporal](/compare/temporal).

### Hatchet

Hatchet is "an orchestration engine for background tasks, AI agents, and durable workflows" that "uses Postgres as a durability layer", with SDKs for Python, TypeScript, Go and Ruby ([README](https://github.com/hatchet-dev/hatchet)).
It is MIT licensed, and Hatchet Cloud includes "1M runs and 1M events free, every month" ([hatchet.run/pricing](https://hatchet.run/pricing)).

Pick Hatchet when you want a Postgres-backed task queue that your own worker programs register against, under MIT.

Windmill fits better when you also want the editor, [auto-generated UIs](../core_concepts/6_auto_generated_uis/index.mdx), apps and 20+ script languages around the queue.
In our [benchmarks](../misc/3_benchmarks/competitors/hatchet/index.mdx), Hatchet performed well on long-running tasks and had high wait and idle times in multi-worker lightweight scenarios.

## Internal UI builders

### Retool, Appsmith and ToolJet

Retool builds internal tools on a visual canvas, and [Retool Workflows](https://retool.com/build-enterprise-apps/workflows) lets you "define your process directly in code".
Its free plan covers up to 5 users, and self-hosting is listed on the Enterprise plan ([retool.com/pricing](https://retool.com/pricing)).
Appsmith is "an open-source low-code platform" under Apache 2.0, with drag-and-drop UI and JavaScript ([README](https://github.com/appsmithorg/appsmith)).
ToolJet is open source under AGPL-3.0, with "60+ responsive components" and JavaScript and Python inside apps ([README](https://github.com/ToolJet/ToolJet)).

Pick one of them when the main deliverable is a screen (admin panels, CRUD views over a database) and the backend logic is small queries.
They have spent years on their component libraries, and that shows.

Windmill fits better when the screen is a front for scripts and workflows that do real work: the same Python or TypeScript runs from the app, a schedule, a webhook or an approval flow, on your own workers.
Windmill's [full-code apps](../full_code_apps/index.mdx) are React or Svelte, and every script already has a [form](../core_concepts/6_auto_generated_uis/index.mdx) without building a UI at all.
See [Windmill vs Retool](./retool.mdx).

## Operations runbooks

### Rundeck

Rundeck "is an open source runbook automation service with a web console, command line tools and a WebAPI" ([README](https://github.com/rundeck/rundeck)), Apache 2.0, maintained by PagerDuty.
PagerDuty's commercial product, Runbook Automation, is offered as SaaS and as [Runbook Automation Self-Hosted](https://www.pagerduty.com/platform/automation/process-software/), with "more than 40 out of box plugin integrations".

Pick Rundeck when your team runs node-oriented jobs (commands and scripts across a fleet of servers) and already uses PagerDuty.

Windmill fits better when runbooks are a mix of API calls, scripts and approvals that other teams trigger from a form, and when the same platform also runs your scheduled jobs and internal tools.
See [Windmill vs Rundeck](/compare/rundeck), and [infrastructure automation](/use-cases/infra-automation) for Ansible, Terraform and PowerShell steps in one flow.

### VMware vRO and vRA, AWX

VMware vRealize Orchestrator (vRO) and VCF Automation (formerly Aria Automation and vRealize Automation, vRA) bundle a workflow engine with a request catalog, and are sold as part of VMware Cloud Foundation.
AWX runs Ansible playbooks with surveys, schedules and workflow templates.
Windmill takes the orchestration role, with Terraform or OpenTofu, Ansible, PowerShell and Python as steps of one flow, while vSphere and the tools those platforms call stay in place.
See the [open source alternative to VMware vRA and vRO](/use-cases/vmware-vra-replacement).

### Microsoft automation tools

Power Automate is Microsoft's automation service for building workflows with little or no code, with connectors to Microsoft and third-party services and desktop flows for automating user interfaces.
Windows Task Scheduler and SQL Server Agent are the schedulers that ship with Windows and SQL Server.
See [Windmill vs Power Automate](/compare/power-automate) and [Windmill vs Task Scheduler and SQL Server Agent](./windows_task_scheduler.mdx).
For PowerShell runbooks and SQL Server packages, see [Windmill vs PowerShell Universal](./powershell_universal.mdx), [Windmill vs Azure Automation](./azure_automation.mdx) and [Windmill vs SSIS](./ssis.mdx).

## What the Community Edition does not include

Some answers above depend on the edition, so check these before choosing the free self-hosted Community Edition.

On any Windmill Cloud plan or on Enterprise Edition:

- Unredacted [audit logs](../core_concepts/14_audit_logs/index.mdx): on the self-hosted Community Edition, audit logs are redacted.
- [Git sync](../advanced/11_git_sync/index.mdx) for workspaces with more than 2 users.
- Schedule error handlers, recovery handlers and schedule-level retries.
  Flow step [retries](../flows/14_retries.md) work on the Community Edition.
- Forms on approval pages, and approver permissions such as disabling self-approval or requiring a group.
- [Dedicated workers](../core_concepts/25_dedicated_workers/index.mdx) and concurrency limits.

On Enterprise Edition only, self-hosted or on Cloud:

- SSO for more than 10 users, SAML and SCIM.
- External secret backends (HashiCorp Vault, Azure Key Vault, AWS Secrets Manager).

On self-hosted Enterprise Edition only:

- The [worker group](../core_concepts/9_worker_groups/index.mdx) management UI, init scripts, autoscaling and step priority.

A self-hosted instance also needs Enterprise Edition for more than 3 workspaces or more than 50 users.
The full list is on the [pricing page](/pricing).
